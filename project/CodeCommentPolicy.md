# コードコメント規約

## 対象

- `application`、`engine`、`resources/shaders`、`main.cpp` を対象とする。
- `externals` と自動生成ファイルは対象外とする。

## 基本方針

- コメントは原則として日本語で書く。
- コードから読み取れる処理の繰り返しではなく、目的、理由、制約、所有関係、更新順序を説明する。
- 技術用語やAPI名は、意味が明確になる場合に英語表記を維持する。

## ファイルコメント

各コードファイルの先頭に `役割:` を付け、そのファイルが担う責務を一文で記載する。
必要な場合は、状態を所有するか参照するだけかも続けて記載する。

```cpp
// 役割: SceneDocumentのEntityとComponentを検索する。
// Sceneデータは参照するだけで、ランタイム状態は所有しない。
```

## クラスと関数

- 公開APIには、呼び出し側が知るべき副作用、失敗条件、座標系、単位を記載する。
- ライフサイクルや所有関係は、クラス定義の近くに記載する。
- 長い処理は、更新段階の理由や順序だけをコメントし、処理内容は関数名で表す。

```cpp
// 親変更後も見た目の位置を維持するため、変更前のワールド行列から
// 新しい親を基準としたローカルTransformを再計算する。
```

## シェーダー

- ファイル先頭に、描画または計算パスの目的を記載する。
- 頂点処理では入力・出力の座標空間を、ピクセル処理では主な合成結果を記載する。
- Compute Shaderでは、スレッドが更新する対象と同期上の制約を記載する。

## 避けるコメント

以下のように、関数名や代入文を日本語で繰り返すコメントは追加しない。

```cpp
// 初期化
// 更新
// 値を代入する
```
